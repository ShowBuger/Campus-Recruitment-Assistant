# Git 提交规范

## 提交格式

```
<类型>(<影响范围>): <简短描述>

<详细说明>

## 变更内容
- 变更点1
- 变更点2

## 影响范围
- 影响的模块/功能
- 受影响的用户场景

## 技术细节（可选）
- 技术实现要点
- 性能影响
- 兼容性说明
```

---

## 提交类型（type）

| 类型 | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | feat(岗位推荐): 添加 AI 智能评分功能 |
| `fix` | 修复 Bug | fix(邮件同步): 修复飞书邮件时间解析错误 |
| `refactor` | 重构代码（不改变功能） | refactor(数据库): 优化查询性能 |
| `perf` | 性能优化 | perf(前端): 优化大列表渲染性能 |
| `style` | 代码格式调整（不影响逻辑） | style(前端): 统一组件命名规范 |
| `docs` | 文档更新 | docs(README): 更新部署文档 |
| `test` | 测试相关 | test(岗位): 添加岗位去重单元测试 |
| `chore` | 构建/工具/依赖更新 | chore(deps): 升级 FastAPI 到 0.110 |
| `revert` | 回退提交 | revert: 回退"添加实验性功能" |

## 简短描述规范

- **使用中文**
- **动宾结构**：添加xxx、修复xxx、优化xxx、重构xxx
- **长度限制**：不超过 50 个汉字
- **首字母不大写**，结尾不加句号
- **描述做了什么**，而非为什么做

✅ 好的例子：
```
feat(岗位推荐): 添加基于简历的智能评分功能
fix(邮件同步): 修复相对时间计算错误
refactor(数据库): 将 SQLite 查询改用参数化方式
```

❌ 不好的例子：
```
feat(岗位推荐): 添加了一个新的功能。  # 太模糊
fix(邮件): bug修复  # 没说清楚修了什么
更新代码  # 缺少类型和范围
```

## 详细说明规范

### 结构要求

1. **空行分隔**：简短描述后空一行再写详细说明
2. **使用中文**：全部使用中文描述
3. **分段清晰**：用 `##` 标题分段
4. **列表形式**：用 `-` 列出具体变更点

### 必需章节

#### 1. 变更内容
列出本次提交的主要变更，每项一行：
```markdown
## 变更内容
- 新增 AI 岗位评分接口 `/api/recommendations/score`
- 添加评分权重配置项
- 实现 S/A/B/C 四级评级逻辑
```

#### 2. 影响范围
说明影响的模块、功能、用户场景：
```markdown
## 影响范围
- 后端路由：/api/recommendations
- 前端组件：RecommendationModal.vue
- 数据库：新增 recommendation_scores 表
- 用户功能：岗位推荐页面展示评分
```

### 可选章节

#### 3. 技术细节
技术实现要点、性能影响、兼容性说明：
```markdown
## 技术细节
- 使用 OpenAI GPT-4 进行语义分析
- 单次请求最多处理 20 个岗位
- 增加缓存机制，相同输入 24 小时内复用结果
```

#### 4. Breaking Changes（破坏性变更）
**如果有不兼容的变更，必须说明**：
```markdown
## Breaking Changes
- API 响应格式从 `{score: number}` 改为 `{score: number, grade: string}`
- 需要重新运行数据库迁移：`python -m app.database migrate`
```

#### 5. 相关 Issue/PR
关联的问题或讨论：
```markdown
## 相关链接
- 相关讨论：#123
- 设计文档：docs/design/recommendation.md
```

## 完整示例

### 示例 1：新功能

```
feat(skills): 添加 AI 技能模块，支持智能招聘分析与数据处理

新增四个 AI 技能模块，用于校招信息智能分析和自动化处理。

## 变更内容

### 1. 岗位智能推荐 (job-recommendation)
- 基于候选人简历和偏好对岗位进行 S/A/B/C 评级
- 评分维度：岗位匹配度、简历证据、技术可迁移性、城市偏好、成长回报
- 输出包含评分、等级、岗位画像、匹配优势与差距
- 单次最多评估 20 个岗位

### 2. 招聘邮件分类器 (recruitment-email-classifier)
- 批量分析招聘邮件，自动识别投递阶段（已投递、机考、面试、OC、已挂）
- 语义实体识别，处理公司简称/全称/品牌名差异
- 支持相对时间计算（72小时内、3天内等）
- 四级决策置信度：AUTO/REVIEW_HIGH/REVIEW_LOW/IGNORE

### 3. 公司岗位信息补全 (company-job-enrichment)
- 基于网络搜索或模型知识补全公司类型和岗位方向
- 输出公司类型标签、岗位方向（最多3个）、结构化备注
- 不覆盖用户手动填写的字段，只追加新内容

### 4. 共享岗位去重 (shared-job-deduplication)
- 对多来源校招记录进行模糊去重
- 适用于同步 GiveMeOC、求职方舟等共享岗位平台
- 批次兼容性检查、公司实体匹配、链接归一化

## 影响范围
- 新增目录：skills/
- 后端路由：/api/ai、/api/recommendations、/api/admin
- 数据处理流程：邮件同步、岗位推荐、记录去重
- 用户体验：自动化程度提升，减少手动标注工作量

## 技术细节
- 所有技能均使用 OpenAI agent 配置
- 严格的输入输出格式校验（JSON Schema）
- 保守的推理策略，不编造未核实的信息
- 支持批量处理，提升自动化效率
```

### 示例 2：Bug 修复

```
fix(邮件同步): 修复相对时间计算导致的截止时间错误

## 问题描述
邮件中"72小时内完成"的相对时间计算错误，导致截止时间比预期早 8 小时。

## 变更内容
- 修正时区处理逻辑，统一使用 UTC+8
- 修复"工作日"计算方式，按自然日而非工作日计算
- 增加相对时间单位测试用例

## 影响范围
- 后端模块：app/routers/auth.py
- 影响功能：邮件截止时间提醒
- 受影响数据：2024-10-20 之后同步的邮件记录

## 修复验证
- 已通过单元测试：test_calendar_event_times.py
- 手动验证了 3 封测试邮件的时间计算
```

### 示例 3：重构

```
refactor(数据库): 优化岗位查询性能，减少 N+1 查询

## 变更内容
- 将分页查询改用 JOIN 预加载关联数据
- 添加公司名称和岗位名称的联合索引
- 缓存常用的筛选条件组合

## 影响范围
- 后端模块：app/database.py
- 影响接口：GET /api/records、GET /api/dashboard
- 性能提升：列表查询从 ~800ms 降至 ~120ms（100条记录）

## 技术细节
- 使用 SQLAlchemy eager loading 替代 lazy loading
- 新增索引：idx_company_job (company, job)
- 缓存 TTL 设置为 5 分钟
```

## 提交注意事项

### ✅ 应该做
1. **一次提交只做一件事**：功能、修复、重构分开提交
2. **提交前自测**：确保代码可运行，测试通过
3. **描述要具体**：说清楚改了什么、为什么改、影响什么
4. **使用中文**：所有描述使用中文
5. **分清主次**：核心变更写在前面，次要变更写在后面

### ❌ 不应该做
1. **不要混合多个不相关的改动**
2. **不要提交调试代码、临时文件**
3. **不要使用模糊描述**："更新代码"、"修改文件"、"bug修复"
4. **不要带 Co-Authored-By**：个人项目不需要署名
5. **不要包含敏感信息**：密钥、密码、token 等

## 工具建议

### Git 提交模板

创建 `.gitmessage` 模板文件：

```bash
# .gitmessage
<类型>(<影响范围>): <简短描述>

## 变更内容
- 

## 影响范围
- 

## 技术细节（可选）
- 

```

配置使用模板：
```bash
git config commit.template .gitmessage
```

### 提交前检查

```bash
# 查看改动
git diff

# 查看暂存区
git diff --staged

# 检查提交信息
git log --oneline -5
```

## 版本号规范（可选）

遵循语义化版本 `MAJOR.MINOR.PATCH`：

- **MAJOR**：不兼容的 API 变更
- **MINOR**：向后兼容的功能新增
- **PATCH**：向后兼容的问题修复

示例：`1.5.4` → `1.6.0`（新增功能） → `2.0.0`（破坏性变更）
