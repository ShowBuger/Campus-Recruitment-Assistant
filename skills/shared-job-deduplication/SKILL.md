# 共享岗位 AI 去重

只根据输入记录判断，不补充外部事实。目标是避免重复招聘入口，同时避免误删不同岗位或不同投递渠道。

## 判断流程

逐个处理候选记录及其相似的现有记录：

1. 确认公司名称是否指向同一主体或同一招聘品牌。忽略常见公司后缀、空格、大小写及括号内地域信息。
2. 确认招聘批次一致。批次不同不得判为重复。
3. 比较岗位覆盖范围：
   - 岗位名称不同但都是同一批次的综合岗位集合、岗位大类或同一招聘项目，倾向判为重复。
   - 岗位方向、工作地点、招聘对象或职位类别明显不同，倾向保留。
4. 比较投递入口：
   - 链接不同不等于记录不同，可能是同一招聘项目的详情页、跳转页或镜像入口。
   - 链接指向明显不同的职位、城市专场或独立岗位时，应当保留。
5. 只有证据足以说明候选已被现有记录覆盖时，才设置 `duplicate=true` 和 `should_add=false`。
6. 信息不足或无法可靠判断时，设置 `duplicate=false` 和 `should_add=true`，防止误删。

## 输入

输入是 JSON 数组。每项包含：

- `candidate_id`：候选记录标识。
- `candidate`：待新增记录，含公司、批次、岗位、链接、城市和方向。
- `similar_records`：公司相似且批次一致的现有或本批次已保留记录。

## 输出

只输出 JSON 数组，不要输出 Markdown 或解释性前缀。每个候选必须且只能返回一项：

```json
[
  {
    "candidate_id": "candidate-1",
    "duplicate": true,
    "should_add": false,
    "matched_record_id": "shr123",
    "reason": "同一公司同一秋招项目，岗位集合已被现有记录覆盖"
  }
]
```

约束：

- `candidate_id` 必须与输入一致。
- `duplicate` 与 `should_add` 必须互为相反值。
- `matched_record_id` 仅在重复时填写；否则为空字符串。
- `reason` 使用不超过 40 个汉字说明关键依据。
